# ระบบวิเคราะห์อาหาร

## แสดงอาหารหลายรายการในภาพ

ผลก่อนกินส่ง `detectedFoods` เป็นรายการอาหารทุกคลาสที่ตรวจพบและมีคะแนนอย่างน้อย 0.25 เรียงตามคะแนน โดยไม่แสดงชื่อคลาสซ้ำ เช่น ข้าวสวยและไข่เจียว รายการนี้เป็นผลคาดการณ์ของโมเดล ไม่ใช่การยืนยันว่ามีอาหารนั้นจริง และแยกจาก `candidates` ที่เป็นตัวเลือกเมนูหลัก 3 อันดับ ค่าโภชนาการยังใช้เมนู/สูตรที่ผู้ใช้เลือก ไม่บวกค่าต่อหนึ่งจานของอาหารทุกชิ้นรวมกัน รายการที่ตรวจพบถูกเก็บกับมื้อก่อนกินและคืนได้เมื่อเปิดแอปใหม่

## หลังกินตรวจเป็นชื่ออื่น

ยึดเมนู สูตร และสารอาหารที่บันทึกก่อนกินเสมอ หากไม่พบคลาสเดิม แต่ตรวจอาหารอื่นได้ จะส่ง `needsMenuConfirmation` พร้อม `candidates` ของพื้นที่ที่ตรวจได้สูงสุด 3 รายการ โดยแนบ `detectedMenu` บอกชื่อที่โมเดลคาดการณ์ ผู้ใช้ต้องยืนยันว่ารายการนั้นคืออาหารเดิมก่อนคำนวณ เช่น ไข่ต้มที่ตรวจหลังกินคือไข่เจียวเดิม ไม่ตั้งเปอร์เซ็นต์และไม่ให้บันทึกอัตโนมัติจากชื่อที่ไม่ตรงกัน การยืนยันใช้เฉพาะพื้นที่และยังตรวจหัวช้อน วิธีเทียบขนาด และขอบเขตปริมาณตามเดิม ถ้าไม่พบพื้นที่เลยให้ยืนยันจานเปล่าหรือปรับเอง ไม่สร้างพื้นที่จากชื่อเมนู

## เปิดเซิร์ฟเวอร์

บนเครื่องนี้ ดับเบิลคลิก `start-food-server.cmd` ที่โฟลเดอร์โปรเจกต์เพื่อเปิดเซิร์ฟเวอร์ด้วย Python 3.12 และเปิดหน้าต่างนั้นค้างไว้ขณะใช้แอป การเปิด Expo อย่างเดียวไม่ได้เปิดเซิร์ฟเวอร์อาหาร หากรีสตาร์ตคอมพิวเตอร์ต้องเปิดเซิร์ฟเวอร์ใหม่

จากโฟลเดอร์ `D:\NCDs_Mobile_Project`:

```powershell
python Backend_API/api_server.py
```

ต้องมี Python packages: flask, numpy, opencv-python, mysql-connector-python และ ultralytics รวมทั้งโมเดลอาหาร `best.pt` และโมเดล COCO segmentation `yolo11s-seg.pt` ใน Backend_API ตัวโมเดลจะโหลดเมื่อวิเคราะห์ครั้งแรก

การตรวจช้อนใช้ YOLO11s-seg pretrained บน COCO จาก Ultralytics เลือกเฉพาะคลาส `44: spoon` ด้วย `classes=[44]`, `conf=0.15`, `imgsz=640`, `retina_masks=True` แล้วใช้ `extract_spoon_bowl` ใน `spoon_bowl.py` ตัดด้ามด้วย PCA และ bottleneck ตามโค้ดที่ผู้ใช้ให้มา พื้นที่อ้างอิงนับเฉพาะพิกเซล mask หัวช้อนที่แยกได้ ไม่ใช่กรอบทั้งคัน ให้เห็นหัวช้อนชัดและมีด้ามในภาพเพื่อช่วยแยกส่วน ใช้ช้อนอันเดิมทั้งสองภาพ หากไม่ได้ mask ที่ใช้ได้จะให้ผู้ใช้ปรับเปอร์เซ็นต์เอง ไม่มีการใช้กรอบทั้งคันแทน

ผลหัวช้อนเป็นการประมาณจาก mask ช้อนทั้งคัน ไม่ใช่คลาสหัวช้อนที่ฝึกแยกโดยตรง อาหารยังใช้พื้นที่กรอบตรวจจับเดิม ไม่มีการสมมติขนาดจริงของหัวช้อน จึงไม่คำนวณ cm_per_pixel โดยไม่มีขนาดอ้างอิงจริง

ดาวน์โหลดน้ำหนักโมเดลหากยังไม่มี (ต้องเชื่อมอินเทอร์เน็ต):

```powershell
python -c "from ultralytics import YOLO; YOLO('Backend_API/yolo11s-seg.pt')"
```

ผลวิเคราะห์แนบ `scaleReference=coco-yolo11s-seg-bowl-pca-v1` เพื่อกันการเทียบพื้นที่หัวช้อนกับค่าจากกรอบช้อนทั้งคันหรือโมเดลเก่า มื้อเดิมที่ยังไม่เสร็จสามารถใช้การปรับเปอร์เซ็นต์เองได้

เปิด MySQL และฐานข้อมูล `ncd_database` พร้อมตาราง `test_nutrition_data` ก่อนวิเคราะห์ ตั้งค่า DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME ผ่าน environment ได้ (ค่าเริ่มต้น localhost:3306, root, รหัสว่าง)

ตรวจ `http://localhost:5000/api/health`: status success หมายถึงเซิร์ฟเวอร์เชื่อมต่อ MySQL ได้ แต่ยังต้องทดสอบโมเดลและข้อมูลตารางด้วยภาพจริง

## เชื่อมมือถือ

ใช้ Expo LAN และ Wi-Fi เดียวกับคอมพิวเตอร์ แอปจะใช้ host ของ Expo พร้อมพอร์ต 5000 โดยอัตโนมัติ ถ้ารัน Python อีกเครื่อง ใช้ tunnel หรือ Android Emulator ให้สร้าง `Mobile_App/.env.local`:

```dotenv
EXPO_PUBLIC_FOOD_API_URL=http://<IP ของคอมพิวเตอร์ที่รัน Python>:5000
```

Android Emulator ใช้ `http://10.0.2.2:5000` เมื่อ Python อยู่เครื่องเดียวกัน จากนั้นเปิด Expo ใหม่ อนุญาต Python พอร์ต 5000 เฉพาะเครือข่ายส่วนตัวใน Windows Firewall หากมือถือเข้า health URL ไม่ได้ อย่าใช้ localhost บนมือถือจริง

สำหรับแอปที่ build ติดตั้งและใช้งานจริง ให้ใช้ HTTPS กับเซิร์ฟเวอร์ที่มือถือเข้าถึงได้ เพราะ iOS/Android อาจบล็อก HTTP การตั้งค่ากล้องใน app.json ต้อง build ใหม่จึงมีผลกับแอปติดตั้ง

Web ใช้ multipart Blob ส่วนมือถือใช้ไฟล์จากกล้อง ถ้าใช้เว็บจาก origin อื่น ตั้ง WEB_ORIGINS เป็นรายการ origin คั่นด้วย comma (เริ่มต้นอนุญาต localhost:8081 และ localhost:19006) กล้องบนเว็บต้องเป็น localhost หรือ HTTPS

## ค่าโภชนาการคงที่ต่อหนึ่งจาน

นำเข้าข้อมูลจากตารางใน `Proposal.pdf` ที่ผู้ใช้ให้มา 8 เมนู (9 สูตรเมื่อแยกไข่เจียวไข่เป็ด/ไข่ไก่) เฉพาะพลังงาน คาร์โบไฮเดรต น้ำตาล โปรตีน ไขมัน และใยอาหารตามที่แอปแสดง ไขมันอิ่มตัวและโซเดียมไม่ได้นำเข้าค่าจากเอกสารนี้ เมนูที่ไม่มีข้อมูลยังเป็น null

ไข่เจียวต้องเลือกสูตรก่อนบันทึก ไม่เลือกสูตรให้โดยอัตโนมัติ ข้าวกะเพราหมูสับไข่ดาวรวมข้าวและไข่ดาวตามสูตร และข้าวผัดใช้สูตรข้าวผัดไก่พร้อมแตงกวา ชื่อที่แสดงบอกสูตรอ้างอิงชัดเจน ก๋วยเตี๋ยวน้ำใสในเอกสารอ้างอิงหนังสือ “เมนู 7 วันสำหรับผู้สูงอายุ” หน้า 21 จึงเก็บ URL แยกจากคู่มือตำรับอาหารมาตรฐานในโรงพยาบาล

ข้อมูลที่ใช้อยู่คือ `menu_nutrition.json` จับคู่ตามชื่อคลาสของโมเดล 32 เมนู ค่าโภชนาการตั้งต้นไม่เปลี่ยนตามพื้นที่ภาพ จำนวนกรอบ หรือช้อน ไม่ใช้ `pixel_per_gram` และค่าสารอาหารต่อกรัมจาก MySQL มาคูณพื้นที่ภาพอีกต่อไป ตาราง MySQL เดิมและ `add_nutrients.sql` เก็บไว้สำหรับข้อมูลเก่า แต่ไม่ใช่แหล่งคำนวณมื้อใหม่

450 kcal ของข้าวต้มปลาเป็นเพียงตัวอย่าง ไม่ใช้เป็นข้อมูลจริง ค่าที่นำเข้าจากตารางที่ผู้ใช้ส่งคือ 426.79 kcal ต่อหนึ่งที่ตามสูตร เมนูอีก 24 เมนูที่ยังไม่ได้รับข้อมูลยังเป็น `null` แอปแสดง “ไม่มีข้อมูล” แทนการสร้างค่าขึ้นเอง ข้อมูลมื้อที่บันทึกก่อนปรับฐานข้อมูลไม่ถูกแก้ย้อนหลัง

การเติมข้อมูลแต่ละเมนู:

- `servingLabel`: ปริมาณอ้างอิง เช่น 1 จาน หรือ 1 ชาม ต้องตรงกับเอกสาร
- `source`: ชื่อหน่วยงาน เอกสาร ฉบับ และหน้า/ตารางที่อ้างอิง ต้องมีแหล่งข้อมูลจึงใช้ตัวเลขสารอาหารได้
- `sourceUrl`: ลิงก์เอกสารถ้ามี
- `nutrition`: calories เป็น kcal, sodium เป็น mg, carbs/sugar/protein/fat/saturatedFat/fiber เป็นกรัม ทั้งหมดต่อหนึ่งหน่วยบริโภคข้างต้น
- ค่า 0 ใช้เฉพาะเมื่อแหล่งข้อมูลระบุว่าเป็นศูนย์จริง ข้อมูลที่ไม่มีให้คง `null` อย่าใส่ตัวเลขตัวอย่างหรือแปลงข้อมูลต่อ 100 กรัมเป็นต่อหนึ่งจานโดยไม่มีน้ำหนักอ้างอิง

เซิร์ฟเวอร์อ่านไฟล์นี้ใหม่เมื่อถ่ายก่อนกิน จึงเติมข้อมูลแล้วใช้งานได้โดยไม่ต้องเปลี่ยนแอป มื้อที่บันทึกก่อนกินแล้วจะใช้ข้อมูลโภชนาการ ณ เวลานั้นเป็นค่าตั้งต้น การเปลี่ยนข้อมูลอ้างอิงไม่แก้ประวัติหรือมื้อที่ค้างย้อนหลัง

## ก่อนกิน / หลังกิน

ถ่ายก่อนกิน → เลือกเมนูจาก 3 อันดับและตรวจค่าอ้างอิงต่อจาน → บันทึกก่อนกิน → ถ่ายภาพหลังกิน (จำเป็นก่อนบันทึกเสร็จ) → เลือก “จานเปล่า กินหมดแล้ว”, “ให้แอปวิเคราะห์อาหารที่เหลือ” หรือ “ปรับเปอร์เซ็นต์เอง” → ยืนยันผลหลังกิน

ก่อนกิน: multipart `mode=before` ใช้ multi-label NMS เพื่อเก็บคะแนนทางเลือกจริงของคลาสอาหาร รวมคะแนนสูงสุดต่อคลาสและส่งไม่เกิน 3 อันดับใน `candidates` พร้อมค่าอ้างอิงและพื้นที่ของแต่ละเมนู ต้องมีอันดับแรกอย่างน้อย 0.25 จึงรับเป็นผลตรวจพบ ทางเลือกคะแนนต่ำกว่านั้นใช้เพื่อให้ผู้ใช้เลือกเอง คะแนนไม่ใช่ความน่าจะเป็นที่สอบเทียบและไม่ต้องรวมเป็น 100% ถ้าพบไม่ถึง 3 คลาสจะไม่เติมเมนูสมมติ ผู้ใช้ต้องเลือกเมนูก่อนบันทึก ค่าตั้งต้นและพื้นที่ที่เก็บจะเป็นของเมนูที่เลือกเพียงหนึ่งหน่วยบริโภค

หลังกิน: ต้องถ่ายหรือเลือกรูปทดสอบก่อนจึงเลือกวิธีและบันทึกเสร็จได้ การรับภาพไม่ได้ส่งวิเคราะห์หรือบันทึกผลโดยอัตโนมัติ เมื่อกดให้แอปวิเคราะห์จึงส่ง multipart `mode=after`, `menu_class` เป็นคลาสที่เลือกก่อนกิน วิเคราะห์เฉพาะพื้นที่เมนูเดิม ไม่อ่านค่าโภชนาการใหม่และไม่แทนที่ข้อมูลก่อนกิน ถ้าเลือกรูปใหม่จะล้างผลวิเคราะห์เดิม

พื้นที่อ้างอิง = พื้นที่กรอบอาหาร / พื้นที่หัวช้อน

เปอร์เซ็นต์ที่เหลือ = พื้นที่อ้างอิงหลังกิน / พื้นที่อ้างอิงก่อนกิน × 100

เปอร์เซ็นต์ที่กินไป = 100 − เปอร์เซ็นต์ที่เหลือ

สารอาหารที่กินไป = ค่าโภชนาการตั้งต้นต่อหนึ่งจาน × เปอร์เซ็นต์ที่กินไป / 100

สารอาหารที่เหลือ = ค่าโภชนาการตั้งต้นต่อหนึ่งจาน × เปอร์เซ็นต์ที่เหลือ / 100

ภาพทั้งสองต้องใช้ช้อนอันเดิม ถ่ายจากมุมและระยะใกล้เคียงกัน ขณะนี้โมเดลเป็น object detection ใช้พื้นที่กรอบตรวจจับ ไม่ใช่ segmentation ของพิกเซลอาหารจริง จึงยังเป็นค่าประมาณและไม่วัดปริมาตร/ความหนาอาหาร หากต้องการพื้นที่อาหารจริงต้องใช้/ฝึกโมเดล segmentation และประเมินกับภาพก่อน–หลังที่มีค่าจริง

โมเดลปัจจุบันไม่มีคลาสจานเปล่า เมื่อไม่พบอาหารจะส่ง `emptyCandidate=true` เพื่อให้ผู้ใช้ยืนยัน ไม่ตั้งเป็นกินหมดโดยอัตโนมัติ หากเป็นจานเปล่าผู้ใช้กด “จานเปล่า กินหมดแล้ว” ได้เหลือ 0% และข้อความกินหมดแล้วทันทีโดยไม่มีตัวเลื่อน หากยังเหลือหรือภาพผิดให้ถ่ายใหม่/ปรับเอง หากไม่เห็นช้อน ตรวจเมนูเดิมไม่พบ หรือพื้นที่หลังมากกว่าก่อนเกิน 10% จะไม่สร้างผลประมาณปลอม แต่ผู้ใช้ยังปรับเองจากภาพได้ ต้องยืนยันผลก่อนบันทึกทุกครั้ง ใช้สัดส่วนเดียวกันกับสารอาหารทั้งจาน ค่าสารอาหารที่ยังไม่มีข้อมูลจะคงเป็น null แม้คำนวณเปอร์เซ็นต์ได้

การตรวจจับอาหารใช้ภาพยาวสุด 1280 พิกเซล และ inference `imgsz=960`, `conf=0.25` ทางเลือกเมนูใช้ conf=0.001 โดยมีเกณฑ์รับเมนูหลัก 0.25 ส่วนหลังกินใช้ conf=0.05 เพื่อค้นหาเมนูที่ผู้ใช้เลือกไว้ กล้องใช้ JPEG quality 0.9 ยังไม่ได้วัดความแม่นยำบนชุดภาพทดสอบ การเพิ่มรายละเอียดไม่ได้เพิ่มชนิดอาหารที่โมเดลรู้จัก

มื้อที่ค้างและประวัติแยกตามอีเมล เก็บในอุปกรณ์ด้วย AsyncStorage ยังไม่ได้ซิงก์ระหว่างอุปกรณ์ มื้อเวอร์ชันเก่ายังคงค่าตั้งต้นเดิมและใช้ปรับเองได้

เพิ่มปุ่ม “เลือกรูปจากคลังภาพ (ทดสอบ)” ชั่วคราวในหน้ากล้องทั้งก่อนและหลังกิน เลือกภาพแล้วดูตัวอย่างก่อนกด “วิเคราะห์รูปที่เลือก” ใช้เส้นทางวิเคราะห์และข้อมูลมื้อเดียวกับกล้อง ไม่ครอปภาพและไม่ส่งภาพทันทีเมื่อเลือก ยกเลิกตัวเลือกภาพได้โดยไม่เปลี่ยนรูปเดิม

เมื่อทดสอบเสร็จ ปิดชั่วคราวได้ด้วย `ENABLE_TEST_PHOTO_LIBRARY = false` ใน `Mobile_App/src/services/test-photo-picker.ts` หากถอดออกทั้งหมด ให้ลบ helper นี้ พร้อม import, handlePickLibrary, picking/gallerySelected, testGalleryButton และตำแหน่งแสดงปุ่มใน scanner.tsx โดยเก็บเส้นทางกล้อง/วิเคราะห์เดิมไว้ ลบการทดสอบส่วนคลังภาพที่เกี่ยวข้องด้วย `expo-image-picker` มีอยู่ในโปรเจกต์ก่อนเพิ่มฟังก์ชันนี้

```powershell
python -m unittest discover -s Backend_API -p "test_*.py"

```

การทดสอบอัตโนมัติจำลองโมเดลและ MySQL ต้องทดสอบถ่ายรูปบนมือถือจริงอีกครั้งเพื่อยืนยันสิทธิ์กล้อง เครือข่าย และความถูกต้องของโมเดล

## การแสดงผลสารอาหาร

หน้าสารอาหารต่อจานแสดงพลังงานเป็นหลอด พร้อมคาร์โบไฮเดรต น้ำตาล โปรตีน ไขมัน และใยอาหาร ตัดไขมันอิ่มตัวและโซเดียมออกจากหน้าจอ แต่รักษาข้อมูลเดิมไว้เพื่ออ่านประวัติเก่าได้ หน้าพลังงานรายวันใช้หลอดเช่นกัน ค่าพลังงานที่ยังไม่มีข้อมูลไม่แสดงเป็นศูนย์ที่ยืนยันแล้ว
